## 老旧内核兼容性复审（第三次追加，用户要求"重新审查"）
- 产出：`.workbuddy/reports/compat-audit-20260902-v1.html`（42 条：6 P1 / 11 P2 / 12 P3 / 13 通过）
- 扫描脚本：`.workbuddy/tmp/compat_scan.py`（52 条正则，JS语法/JS API/CSS/HTML 四类，可回归复用）
- **最重要结论：JS 零 ES6+ 语法**（无 let/const/箭头/模板串/解构/展开/for-of，全 var + 函数表达式）→ **不需要 Babel**。不要为兼容引入构建，会毁掉"单文件自包含"优势
- **CSS 真问题收敛到一个根因：全站 70 个自定义属性定义 / 225 处 var() 引用**（index 25/98、download 25/85、404 20/42）。IE11 不支持 → 含 var() 的声明整条丢弃 → 白底黑字直角宋体，品牌视觉 100% 丢失，但内容仍可读
- **发现上午 C1 补丁的遗留缺陷**：`@supports not (aspect-ratio)` 降级（index:277-282）在 IE11 上等于没降级——IE11 连 `@supports` 都不支持，兜底块整体被丢弃 → 视频容器高度塌陷为 0。**通用原则：用 @supports 写的兜底，救不了不支持 @supports 的浏览器。方向应改为「默认 padding hack + @supports 内升级」**
- 仍存在的真问题（按优先级）：
  1. **HTML-01 缺 `<meta http-equiv="X-UA-Compatible" content="IE=edge">`**（index/download 都没有，仅 404.html:4 有）→ IE 可能落兼容性视图降 IE7/IE8 文档模式 → 前面所有兼容修复全白做。**必须最先补**
  2. **JS-03 `Element.closest()`**（index:690 / download:532,610）→ IE11 抛 TypeError；download:610 导致**整卡下载彻底失效**（唯一"功能死掉"级别的 JS 问题）
  3. **JS-02 `window.scrollY`**（index:652,666 / download:514,555）→ IE 全系 undefined；download:555 返回顶部按钮**永不显示**
  4. **JS-04 `classList.toggle(cls,force)` 第二参**（5 处）→ IE11 忽略 → 导航条滚动时高频闪烁
  5. **JS-05 `e.key==='Escape'`**（index:723 / download:604）→ IE9-11 与 EdgeHTML 返回 `'Esc'` → 弹窗关不掉
  6. **JS-06 `scrollTo({top,behavior})`**（download:558）→ IE 行为未定义
  7. **CSS-03 404.html:64,80 `filter:blur(60px)`** → IE11 无 CSS filter → 46vw/50vw 纯色硬边大圆压背景
  8. **CSS-05 flex gap ×30** → IE11 全丢，元素挤在一起（最易一眼看出的 IE 特征）
  9. **DEP-03 YouTube iframe 无兜底**（index:571）→ YouTube 2020 起不支持 IE11 + 大陆不可达，两类用户同时空白
- 已正确降级的项（保持，勿回退）：`IntersectionObserver` 特性检测 else 分支、`audio.play()` Promise 判空、`100svh` 前有 100vh、`env()` 失败回退基础值、`background-clip:text` 双前缀齐全、SVG `xlink:href`（旧 WebKit 需要）、404 页全部 JS 仅 ES5/IE9+
- **实测新数据**：TLS 1.0 / 1.1 / 1.2 握手**全部返回 200** → Win7 IE11 也能连上（兼容利好，但 Cloudflare 最低 TLS 仍 1.0，属安全弱点，提到 1.2 就等于放弃 Win7/IE11）
- **CDN 边缘节点第 3 次漂移**：09-02 实测 `x-github-edge-region: sea`（西雅图）+ `X-Served-By: cache-lax-*`（洛杉矶）。对照 08-29 东京 HKG/NRT、08-31 孟买 DEL/BOM → 三次三落点，调度极不稳定
- **战略判断（写进报告第 6 节）**：本站用户是 VN/PH/欧美 CF 玩家，IE11 占比大概率 <0.1%，而东南亚中低端 Android 的 UC/QQ/X5 内核（Chrome 30-57）可能占 5–15%。**Chrome<49 内核会复现与 IE11 同款的 var() 崩塌**。所以修复应优先"跨内核通杀"项（var 兜底 / closest / scrollY / aspect-ratio 方向），一份投入同时惠及 IE11 + EdgeHTML + 旧 X5
- **前置动作**：站点零统计埋点，无法量化老内核占比。动手前先去 Cloudflare 面板导出 UA 分布（5 分钟），否则投入排序全是猜
- 方案结论：推荐 A（渐进增强改写，约 2h，零构建）+ D（IE UA 检测提示条，15min，保底）；**不建议 C（Babel/PostCSS 构建）**；**禁止引入 polyfill.io 之类公共 CDN**（会摧毁零外部依赖优势 + 该域名有供应链安全事故前科），需要补的一律内联
