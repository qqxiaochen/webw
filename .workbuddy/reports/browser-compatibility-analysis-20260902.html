2严重问题（C1，必须处理）

2.1 滚动渐入导致 IE/极旧浏览器整页不可见

根因：.reveal{opacity:0;transform:translateY(28px)}（index:361 / dl:321）默认隐藏，依赖 JS 添加 .in。但揭示逻辑用了 revealEls.forEach(...)；IE 既无 IntersectionObserver 也无 NodeList.forEach，进入 else 分支（index:676 / dl:546）即抛 TypeError，.in 从未添加 → 所有 .reveal 区块永久 opacity:0。

影响版本：IE 11 及任何不支持 NodeList.forEach 的旧浏览器 → 首屏 Hero 以下内容全黑/全透明。

降级方案：① 不用 NodeList.forEach，改用 Array.prototype.forEach.call 或 for 循环；② 更稳妥——让 .reveal 默认可见，仅当 JS 就绪后再隐藏（加 .js 类门控）：

/* CSS */
.reveal{opacity:1}                 /* 默认可见，无 JS 也能看 */
.js .reveal{opacity:0;transform:translateY(28px);transition:...}
.js .reveal.in{opacity:1;transform:none}

/* JS 顶部 */
document.documentElement.className += ' js';
/* 遍历统一用兼容写法 */
var els = document.querySelectorAll('.reveal');
Array.prototype.forEach.call(els, function(el){ io.observe(el); });
✓ 这样即使脚本在旧浏览器出错，内容仍可见（优雅降级），且现代浏览器动画不受影响。

2.2 inset 简写使环境渐变背景层塌陷

根因：body::before（index:94 inset:-12%）、.glass::before/::after（index:113/137）、.modal-backdrop（index:297）等使用 inset 简写定位。inset 在 Chrome<87、Safari<14.1、Firefox<66 不被识别 → 绝对/固定定位元素失去 top/right/bottom/left → 尺寸塌为 0。

表现：首屏彩色光斑背景（body::before）整层消失，仅剩纯色底；玻璃面板的高光/内反射伪元素错位；遮罩层失效。

降级方案：把 inset 展开为四向显式值（现代浏览器两种写法并存无副作用）：

/* 改前 */ body::before{position:fixed;inset:-12%;...}
/* 改后 */ body::before{position:fixed;top:-12%;right:-12%;bottom:-12%;left:-12%;...}
/* .glass::after 改后 */ .glass::after{position:absolute;right:0;bottom:0;left:0;height:38%;...}

2.3 aspect-ratio 使 YouTube 嵌入在旧浏览器高度为 0

根因：.video-frame{aspect-ratio:16/9}（index:277）配合 .video-frame iframe{height:100%}。旧浏览器不识 aspect-ratio → 父容器无高度 → iframe 100% 解析为 0 → 视频区不可见。

影响版本：Chrome<88 / Safari<15 / Firefox<89。

降级方案：经典 padding 比例 hack 作为回退（现代浏览器 aspect-ratio 会覆盖）：

.video-frame{position:relative;aspect-ratio:16/9;
  padding-top:56.25%; /* 回退：16:9；aspect-ratio 支持时此值被忽略但无害 */}
.video-frame iframe{position:absolute;inset:0;width:100%;height:100%}
/* 注意：同时给 iframe 显式 inset:0（见 2.2 展开写法） */

2.4 404.html 缺失 DOCTYPE → 怪异模式（Quirks Mode）

根因：404.html 第 1–2 行为空行，<html> 前无 <!DOCTYPE html>（已实测 head -c 400 无 DOCTYPE）。这会导致所有浏览器进入怪异模式：盒模型按 IE5 解析、box-sizing/ 百分比高度 / 定位行为漂移，叠加其已写的 -ms-transform 兼容代码反而自相矛盾。

降级方案：在文件最顶部加 <!DOCTYPE html>，并修正 lang 与可缩放视口（当前 user-scalable=0 违反无障碍）：

<!DOCTYPE html>
<html lang="zh-CN">
<meta name="viewport" content="width=device-width,initial-scale=1">

4轻微差异（C3，可忽略）

  • 100svh / env(safe-area-inset-bottom)：index 已对 Hero 写 min-height:100vh 回退；旧浏览器仅缺失刘海屏安全区适配，无实质损害。
  • scroll-behavior:smooth / window.scrollTo({behavior:'smooth'})：旧浏览器退化为瞬间跳转；scrollTo 传对象在 IE 会被忽略 → 返回顶部失效。建议改 window.scrollTo(0,0) 或在对象外再调一次数值版。
  • prefers-reduced-motion：旧浏览器不识别 → 动画照常播放，仅影响"减少动态"偏好用户，可接受。
  • mask-image（404 光泽）：不支持时光带呈矩形而非羽化，纯装饰，无影响。
  • position:sticky（弹窗标题栏）：Safari<13 不吸附，弹窗滚动时标题栏随内容滚走，功能正常。
  • mix-blend-mode:screen（404）：IE 不支持 CSS 滤镜混合，光带直接叠绘，无影响。

5JS 兼容性总评与最低安全运行方案

脚本本身刻意使用 ES5 写法（var / IIFE / 无箭头函数 / 无模板字符串），这点对旧浏览器友好。但有两处"现代 DOM API"是隐患：NodeList.forEach（C1）与 Element.closest（C2）。IntersectionObserver 已有降级分支（好），audio.play() Promise 已用 if(p&&p.catch) 防御（好）。

✓ 推荐"最低安全目标"：保证 IE11 及以上能看全内容、核心按钮可用。只需落实 §2.1（reveal 默认可见 + 遍历兼容）、§2.2（inset 展开）、§2.3（video 比例 hack）、§2.4（404 DOCTYPE）四项，即可让 IE11 与 5 年前主流浏览器正常访问；其余 C2/C3 为视觉减分，可按优先级后续补。
