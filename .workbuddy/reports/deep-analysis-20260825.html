三、核心发现：两套技术栈严重割裂

这是本项目最突出的结构性问题。index.html 与 download.html 看似同一站点，实则处于两个时代：

✓ index.html · 现代栈（已落地）

依赖0 外部依赖，全内联
体积36 KB 单文件
样式CSS 变量 + 玻璃拟态
交互原生 JS，IntersectionObserver
响应式完整（含 hover:none / 安全区）
可维护性高

✗ download.html · 旧栈（残破）

依赖jQuery + core.js + coret.js
标记UIkit 类（uk-*）遍布
UIkit 框架未加载（无 uikit.js / uikit.css）
网格/弹窗/标签依赖 UIkit，将失效
响应式弱（固定 c1200 容器）
可维护性低，与首页割裂
⚠ 下载页事实性故障： download.html 第 18–182 行大量使用 uk-navbar / uk-grid / uk-tab / uk-card / uk-modal / uk-scrollspy / uk-toggle 等 UIkit 组件类，但 <head> 仅引入 core.css / coret.css / jquery.min.js / core.js / coret.js，从未加载 UIkit 运行时。静态检查确认 static/js/ 下无 uikit 文件、core.css 仅含 1 处 uikit 残留样式。结果：下载页的网格布局、卡片、标签页、弹窗、返回顶部等依赖 JS 行为能力基本失效，用户可能看到未排版的裸内容。

六、优化路线图建议

阶段 A（紧急，1 天内）

  • 修复下载页：二选一——① 将下载页也重写为首页同款自包含玻璃风格（推荐，彻底统一）；② 若保留旧栈，则补全 UIkit CSS/JS 并验证 tab/modal/grid 正常。
  • 修复 VN 死链：补充 down/vn/ 文件，或从下载页移除 VN 卡片直到就绪（避免 404）。

阶段 B（清理，半天内）

  • 删除死文件：webw.zip、down/speed/、static/footer.js、多余 jQuery、yii.js、未用 APlayer/Meting/base/popup、根 core.css 副本。
  • git 瘦身：确认 .gitignore 已排除 *.zip；对历史大文件视情况用 git filter-repo 清理（谨慎，需备份）。
  • 统一下载页与首页的技术栈与视觉语言。

阶段 C（加固，持续）

  • 合规对齐：统一支付渠道与「Except China」声明的表述，避免境内域名与免责声明直接冲突。
  • SEO 补全：下载页补 lang="zh-CN" + description/OG；首页 keywords 精简为自然词。
  • 提交规范：改用语义化 commit（如 fix: 修复下载页 UIkit 缺失）。
  • 下载页应为纯静态直链列表（无需 jQuery/UIkit），与首页风格一致即可，复杂度最低。
