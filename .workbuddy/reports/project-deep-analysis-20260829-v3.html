1执行摘要

先给结论，再给证据。

⚠ 最重要的三件事

1. 之前的部署结论是错的。08-27 的 v2 报告判定站点托管在 Cloudflare Pages。本次实测响应头中出现 X-GitHub-Request-Id、x-github-edge-region: japaneast、X-Fastly-Request-ID —— 这三项是 GitHub Pages 的独有特征。真相是：Cloudflare 仅作 DNS + 反向代理，真正的源站是 GitHub Pages。

2. 由此产生一个 P0 定时炸弹。CI 工作流 deploy-pages.yml 里有一行 rm -f CNAME，动机是"只部署到 github.io、保留 Cloudflare 上的主站"。但主站本身就在 GitHub Pages 上 —— 这个前提不存在。每次部署都在删除自定义域名的凭证文件，目前没炸只是因为域名绑定持久化在 GitHub 服务端，一旦触发重校验，全站自定义域名即失效。

3. VN 下载是 100% 死链。download.html 首卡 VN 的主按钮指向 /down/vn/PaoMianHax-Vn-211103-2(Pass123).zip，线上实测 404，本地 down/ 下根本不存在 vn 目录。这不是网络波动，是结构性缺文件。三服下载入口里挂了一个，且是排在第一位的那个。

矛盾点：工作流注释写着"镜像模式：仅部署到 *.github.io，保留 Cloudflare 上的 www.paomfz.com"—— 这句话描述的架构不存在。Cloudflare 上没有独立的站点副本，它只是一个转发层。

P0 风险：rm -f CNAME

# .github/workflows/deploy-pages.yml
# 镜像模式：仅部署到 *.github.io，保留 Cloudflare 上的 www.paomfz.com
# 移除 CNAME 文件，避免 GitHub Pages 尝试绑定自定义域名
- name: Exclude custom domain (mirror on github.io only)
  run: rm -f CNAME   ← 每次部署都执行

仓库根目录确实提交了 CNAME（内容 www.paomfz.com，无结尾换行）。GitHub Pages 的自定义域名绑定有两种来源：仓库里的 CNAME 文件，或 Settings 里的手动配置。目前域名能访问，说明绑定是持久化的服务端配置；但只要 GitHub 哪次重新以仓库文件为准做校验，把 artifact 里的 CNAME 删掉就会直接导致自定义域名解绑，www.paomfz.com 全站 404。

更直接的证据：如果这套"镜像"设计真按预期工作，那么 www.paomfz.com 应该完全不经过 GitHub Pages —— 但它的响应头里全是 GitHub Pages 的特征。设计意图与实际情况已经完全脱节。

缺陷清单

BUG 404.html 缺少 <!DOCTYPE html> —— 三页中唯一没有的。浏览器会以 quirks mode 渲染，盒模型、行高、字体继承都可能出现偏差。这个页面是 GitHub Pages 的自定义 404 页，所有走错 URL 的用户都会看到它。

A11Y 404.html 的 viewport 禁用缩放：maximum-scale=1, minimum-scale=1, user-scalable=0。违反 WCAG 1.4.4（可调整文本大小），且 index / download 两页都是标准写法 —— 三页不一致。404 页面的用户往往是视障或误输入的，最不该禁用缩放。

A11Y 404.html 声明 lang="en" 但正文是中文（"网页找不到惹 ╥﹏╥..."）。屏幕阅读器会用英语语音引擎读中文，输出不可辨识。

SEO download.html 没有 <h1>，标题层级从 h3 直接开始（4 个 <h3> 是三张下载卡的标题）。index.html 有 1 个 h1 + 2 个 h2 + 5 个 h3，结构正常。下载页是转化核心页，缺 h1 会让搜索引擎难以判断页面主题。

SEC 10 个 target="_blank" 全部缺少 rel="noopener noreferrer"（index 6 个 + download 4 个）。新开页面可通过 window.opener 反向操控原页面（tabnabbing），同时会泄漏 referrer。涉及 Discord / Telegram / YouTube / 支付站外链。

一致性 页脚地域声明不一致：download.html 写 "PaoMian Hax is a team that since 2099 brings quality services in various areas. (Except China)"，index.html 同一句话没有 "(Except China)"。同一套页脚两种版本。

SEO keywords meta 仍是黑帽堆砌：index.html 里塞了 20+ 个重复变体（CFWE HACK 出现 3 次、HACK CF 2 次…）。Google 自 2009 年起完全忽略 keywords，百度也早已降权。这段对排名零贡献，反而是明显的垃圾信号，建议直接删除。

维护 三页 CSS 高度重复：导航系统、玻璃质感（backdrop-filter / 渐变描边 / 高光）、按钮组、modal、footer、reveal 动画在两个页面里各写了一遍。download.html 相对 index.html 至少有 60% 的 CSS 是复制粘贴。改一处要改两处 —— 8-28 改版 + 8-29 回退之所以要动三个文件、备份六份，根源就在这里。

细节 404.html 仍用 xlink:href 引用 SVG symbol。SVG2 已废弃该属性（改用 href），现代浏览器虽仍兼容，但属技术债。另外 404.html 的 favicon 用绝对路径 /favicon.ico，另两页用相对路径 static/favicon.ico —— 两种写法都能工作，但不一致。

7安全与合规

静态站点的攻击面很小，但 Cloudflare 层可以零成本补上所有头。

缺失的响应头

响应头状态影响
Strict-Transport-Security缺失首次 HTTP 访问可能被劫持（虽无登录态，风险有限）
Content-Security-Policy缺失无法约束内联脚本与外部 iframe（YouTube）的行为
X-Frame-Options缺失站点可被任意第三方 iframe 嵌套（点击劫持）
X-Content-Type-Options缺失MIME 嗅探风险
Referrer-Policy缺失跳往外链时泄漏完整 URL

这五个头在 Cloudflare 上通过 Rules → Response Header Transform 或 _headers 文件配置即可，不需要动代码。注意：GitHub Pages 不支持 _headers 文件（那是 Cloudflare Pages / Netlify 的特性），必须在 Cloudflare 面板里配。

合规风险

支付渠道与地域声明矛盾。index.html 的店铺按钮指向 mall.909net.cn（.cn 境内域名，第三方发卡平台），另有 pay.paomfz.com。但页脚同时声明 "Except China"。使用境内支付渠道与"不服务中国"的声明并存，逻辑上不能自洽。若确需维持该声明，建议统一改用境外支付渠道；若实际服务中国用户，则应删除该声明 —— 二选一，不能两头都占。
中国大陆可达性：index.html 嵌入了 YouTube iframe（youtube.com/embed/Mr6FaTdi9As），社群入口是 Discord 与 Telegram —— 这三者在中国大陆均不可直接访问。目标用户若含中文用户，视频区会渲染成空白框，两个社群卡片点了也打不开。建议：视频改镜像源或提供备用播放器提示，社群增加 QQ 群 / 微信入口。

8性能与 SEO

性能

  • 文档体积极小：三页 gzip 后 9.3 / 7.6 / 4.9 KB，首屏 HTML 几乎零网络成本。这一点做得很好。
  • 最大瓶颈是 YouTube iframe：完整播放器脚本 + 相关资源约 1 MB+。已有 loading="lazy"，但进入视口后仍会一次性拉取。建议改为点击后再加载（facade 模式，用静态封面图占位）。
  • backdrop-filter 密度偏高：index 16 处、download 16 处、404 10 处。这是 GPU 密集型属性，中低端安卓机上滚动会掉帧。当前已有移动端降级策略（blur 值调低），方向正确，建议再评估是否所有元素都需要实时模糊。
  • 未见 content-encoding 响应头：GitHub Pages 默认会做 gzip/brotli，此处未观测到可能被 Cloudflare 剥离，建议用 WebPageTest 从境外节点复核一次。
  • HTTP/2 未能验证：从当前网络环境探测失败，无法确认。Cloudflare 默认开启，实际应该已支持。

SEO

  • 已具备 canonical、OG（title/description/type/url/image/locale）、Twitter Card、description、author、robots、lang。这是 08-25 重写后补上的，比原始版本有质的改善。
  • 缺失 sitemap.xml —— 全站仅 3 个页面，手写一份即可，能让搜索引擎完整收录。
  • 缺失 robots.txt —— 建议补充并指向 sitemap。
  • 缺陷 OG image 用的是 static/favicon.ico（7 KB 的 ico）。社交平台分享时会显示一个极小的图标。建议制作 1200×630 的分享图。
  • 缺陷 download.html 缺 h1（见 6 节）。
  • 冗余 keywords 黑帽堆砌（见 6 节）。
  • 提示 百度与 Google 的站点验证文件均已部署并可通过 URL 访问，说明站长平台已接入 —— 但既然已接入，就更应该补上 sitemap。
