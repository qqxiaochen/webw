总体结论：这是一个结构清晰、视觉完成度高的小型纯静态官网，业务逻辑集中在两个内联脚本中、可读性好；但存在严重的重复代码（CSS 53%）、仓库膨胀（1.5GB 历史）、多处线上死链与失效转化路径，以及每次部署会删除 CNAME 的 CI 隐患。当前最紧急的是恢复主转化路径（购买 / 店铺 / VN 下载）并消除部署解绑风险。

1架构概览

站点采用无后端、无构建、纯静态自包含单文件架构。三页各自内联全部 HTML+CSS+JS，无外部 CDN 依赖、无框架。部署链路为「开发者 push main → GitHub Actions CI → GitHub Pages → Cloudflare 反向代理回源 → 用户」。

关键架构事实（实测）

  • Cloudflare 仅为转发层，无独立站点副本；线上响应头含 X-GitHub-Request-Id + Via: varnish + X-Fastly-Request-ID，证实回源 GitHub Pages。
  • CI 每次执行 rm -f CNAME（.github/workflows/deploy-pages.yml:31），注释称"仅部署 github.io、保留 Cloudflare 主站"——但该前提不成立，主站就在 GH Pages 上，每次部署都会删除自定义域名凭证，随时可能解绑导致全站 404。
  • 无服务端逻辑、无数据库、无 API；下载为静态文件直链，支付/社群跳转至第三方外链。

数据流

  • 内容数据：硬编码在 HTML（功能卡、下载卡、TOS 文案），无数据源。
  • 下载产物：down/{ph,we,speed}/*.zip 静态直链。
  • 转化出口：pay.paomfz.com（支付）、mall.909net.cn（店铺）、Discord / Telegram（社群）。
  • 媒体：static/music.mp3（3.1MB，加载即尝试自动播放）、YouTube 嵌入 iframe。

3技术栈及其合理性

维度选型合理性评价
HTML原生语义标签 + 内联 SVG 图标无外部图标库，零网络依赖；SVG 线性图标可维护合理
CSS原生 CSS + CSS 变量设计令牌 + backdrop-filter 玻璃拟态无构建、无预处理器；变量化 tokens 利于主题统一合理

部署GitHub Pages + Cloudflare免费、免运维；但 CI 删 CNAME 是自制风险有隐患
依赖零第三方依赖无供应链风险、加载快优秀
资产管线手工维护二进制无压缩/指纹/版本化；死文件与重复文件堆积不足
选型结论：技术栈与"轻量营销站"的定位高度匹配，零依赖是显著优点。主要问题不在"用什么"，而在"如何组织与维护"——重复内联导致任何视觉改动要改三处，且二进制资产缺乏治理。

可读性 8/10

视觉改版需同步 3 文件；无构建校验，易遗漏

有 rAF 节流、IntersectionObserver 降级、prefers-reduced-motion；但弹窗无焦点陷阱

亮点

  • 完整的 设计令牌化 :root 体系，深色玻璃视觉统一、完成度高。
  • 交互脚本防御性较好：rAF 节流、无 IO 降级、prefers-reduced-motion 全量关闭动画、hover:none 清理触屏粘滞。
  • SEO/元信息齐全：canonical、OG、Twitter Card、theme-color、lang、description 完备。
  • 零第三方依赖，无供应链与版本漂移风险。

短板

  • CSS 重复 53%（217/410 行与 download 完全相同），违背 DRY。
  • 无 h1 于 download.html（用 .dl-head-en 充当），404.html 以 h5 当主标题、缺 DOCTYPE、lang="en" 但正文中文、0 处 aria-label。
  • 10 个 target="_blank" 缺 rel="noopener noreferrer"（反钓鱼隐患）。
  • 下载卡整卡可点击但无 role/tabindex/键盘事件，键盘与读屏用户不可达；模态无焦点陷阱。
  • 音乐自动播放回归（见 P0）。

7改进建议（优先级路线图）

阶段一 · 止血（P0，预计 1 天）

  • 修 CI：删除 deploy-pages.yml 中 rm -f CNAME，或改为保留自定义域名部署；部署后验证 www.paomfz.com 仍可解析。
  • 恢复转化路径：修复/替换 pay.paomfz.com（403）与 mall.909net.cn（失联），或将 Purchase/店鋪按钮指向可用入口；上线前用 curl 验证返回 200。
  • 修 VN 死链：上传真实 VN 包到 down/vn/，或在未就绪时禁用下载按钮（仅保留 Intro）。
  • 音乐自动播放：移除 index.html:740-742 的加载即播放与 document click 兜底，改为纯手动开关（保留右下角按钮即可）。

阶段二 · 减负（P1，预计 2-3 天）

  • 抽共享样式：将 :root + .glass + .btn + 响应式断点抽到 static/site.css，三页 @import/<link> 引用（权衡：会破坏"单文件自包含"，但换取可维护性；若不接收，则接受重复并加注释约定）。
  • 清理死资源：删除 down/speed×3（字节相同）、down/ph/7A638484.zip、static/images 13 个零引用文件；释放 ~70MB。
  • Git 治理：git gc --aggressive 或历史重写（如 git filter-repo）消除 1.5GB；将 .workbuddy/ 加入 .gitignore（当前仅忽略 backups/memory/*.bak*，漏了 reports/tmp）。
  • 补安全响应头：Cloudflare → Rules → Transform/Response Headers 加 HSTS/CSP/XFO/Referrer-Policy。
  • 可访问性：补 download.html 的 h1、404.html 的 DOCTYPE/lang/main/aria；10 个外链加 rel="noopener noreferrer"；下载卡加 role="button" tabindex="0" + 键盘事件；弹窗加焦点陷阱与关闭后焦点复位。

阶段三 · 提质（P2，按需）

  • 规范提交信息（ Conventional Commits），便于追溯。
  • 统一两页合规声明与页脚年份；删除 "since 2099" 占位。
  • 将 YouTube iframe 加大陆访问兜底（失败时不留白屏）。
  • 对下载产物引入版本化/校验和，避免"版本号写在 HTML"的硬编码漂移。
