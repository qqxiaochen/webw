P0 · 新

背景音乐自动播放回归 —— 08-25 的修复被推翻

8-25 重写时明确移除的 autoplay 行为，在 08-29 17:07 的改动中被重新加了回来，且比原始版本更激进：不但页面加载即尝试播放，还挂了一个 document 级的一次性 click 监听 —— 用户点击页面任意位置（导航、下载按钮、条款链接）都会触发音乐播放。同时 preload='auto' 会让 3.1 MB 的 mp3 在首屏就被完整拉取。

该改动已上线（线上 Last-Modified: Sat, 29 Aug 2026 09:29 GMT）。工作区里的备份 index.html.bak-20260829-1707 仍保留着「懶加載，默認關閉」的正确版本，可作为回滚源。

// index.html:740-742 —— 页面加载即执行 initAudio(); tryPlay(); // index.html:714-720 —— 播放被浏览器拦截后的兜底，性质更严重 document.addEventListener('click', function handler(){ tryPlay(); // 点哪儿都会响 document.removeEventListener('click', handler); }, {once: true});
建议修复删除第 740-742 行的自动调用，删除 714-720 的 document click 兜底，把 preload 改回 'none'，恢复为纯手动点击开关。或直接把音乐功能整体下线 —— 对一个下载站来说，3.1 MB 自动播放音频的收益远小于体验损失。
P0 · 新

支付入口 403 —— 主转化路径断裂

index.html 上有 2 个 Purchase 按钮（导航栏 + Hero 主行动区），全部指向 https://pay.paomfz.com/。实测该子域返回 HTTP 403。

$ curl -I https://pay.paomfz.com/ HTTP/1.1 403 Forbidden content-type: text/html; charset=UTF-8 （5.3 KB 错误页）

同时 Hero 的第一个 CTA「店鋪」指向 mall.909net.cn，实测连接失败（curl 退出码 000，无响应）。两个购买入口当前都不可用。

建议修复先确认 403 是 Cloudflare 防火墙规则误伤（如 bot fight mode、地区拦截）还是源站故障。若是规则误伤，为 pay. 子域单独放行；若是源站故障，先把两个 Purchase 按钮临时改为指向 Discord/Telegram 客服，避免流量白白流失。

P0 · 遗留

CI 每次部署都在删除 CNAME —— 定时炸弹

.github/workflows/deploy-pages.yml 第 28-31 行有一条 rm -f CNAME，注释写的是「镜像模式：仅部署到 *.github.io，保留 Cloudflare 上的 www.paomfz.com」。但实测证明这个前提不成立 —— Cloudflare 上没有独立站点副本，它只是反向代理，真正的内容源就是 GitHub Pages。

也就是说，每次 push 都在亲手删掉自己站点的自定义域名凭证。目前站点仍在线，是因为 GitHub 解绑自定义域名是异步、有延迟的，但一旦触发，全站立刻 404。

# 线上实测：www.paomfz.com 的响应头，GitHub Pages 特征齐全 X-GitHub-Request-Id: DDE0:2872A6:45F09D:4ED17C:6A955896 x-github-edge-region: centralindia Via: 1.1 varnish X-Served-By: cache-bom-vanm7210032-BOM X-Fastly-Request-ID: 2b2dcfc3e8a8970575a2646d8696a3b230399a57 CF-RAY: a33b615079d059e8-DEL
建议修复直接删掉 workflow 里那两行 rm -f CNAME。CNAME 文件已在仓库中且已跟踪，保留它对 github.io 镜像没有任何副作用 —— GitHub Pages 在 CNAME 存在时会把 *.github.io 请求 301 到自定义域名，这正是想要的行为。

02部署架构与线上实况

链路本身是健康的（push 后约 1 分钟完成部署），但边缘节点的地理分布相比 8-29 出现了明显劣化。

请求链路

用户 → Cloudflare（DNS + 反向代理）→ 回源 GitHub Pages（Fastly CDN）

Cloudflare 层不持有站点副本，纯转发。这意味着 Cloudflare 的缓存规则、防火墙规则会直接影响全站可用性 —— 前面那个 pay. 子域 403 就高度疑似出在这一层。

安全响应头：依然全空

首页响应中没有任何一个安全相关头：HSTS、CSP、X-Frame-Options、X-Content-Type-Options、Referrer-Policy 全部缺失。反倒有一个 Access-Control-Allow-Origin: *，意味着任意第三方站点都可以用 JS 读取本站页面内容。

# 首页响应头中与安全相关的部分 （HSTS / CSP / XFO / XCTO / Referrer-Policy —— 全部缺失） Access-Control-Allow-Origin: * ← 非预期开放 Cache-Control: max-age=600
好消息这类头对纯静态 GitHub Pages 站点来说，无法在源站配置，但可以在 Cloudflare 的 Transform Rules / 响应头规则里统一加上，无需改代码。这是投入产出比最高的一项：在 Cloudflare 面板加 4 条规则即可覆盖全站。

历史上一共提交过 47 个 down/ 下的文件版本 —— down/ph 独占 31 个，down/we 15 个。每一个都是 30 MB 左右、彼此内容完全不同的二进制包，Git 无法做增量压缩，于是 55 个 >1 MB 的 blob 硬生生堆出了 1.43 GB。

$ git count-objects -v count: 463 # loose 对象 size: 1471169 # KB ≈ 1.4 GB in-pack: 0 # ← 从未 gc / 从未打包 packs: 0
建议修复（分两步，第二步不可逆，需先备份）① 低成本：先跑一次 git gc --aggressive --prune=now，仅打包整理，通常能压掉 20-40%，不丢任何历史。② 彻底方案：用 git filter-repo（或 BFG）把 down/ 从全部历史中剥离，改用 GitHub Releases 或对象存储托管这些 ZIP，HTML 里改为指向外链。这一步会重写全部 commit hash，需要强制推送并协调所有协作者，操作前务必 git clone --mirror 留一份完整备份。

05P2 优化项

SEO

keywords 黑帽堆砌

index.html 第 7 行的 keywords 塞了 20 多个重复变体，CFWE HACK 出现 3 次、HACK CF 2 次。主流搜索引擎早已完全忽略 keywords meta，它不但没用，还是典型的 spam 特征信号。建议直接整行删除，把精力放在 title / description / canonical 上（这三个目前写得不错）。

工程

提交信息 76 次里有 75 次是「1」

git log --oneline 里 76 个提交，75 个 message 是单字符「1」，唯一例外是 CI workflow 那次和一次 GitHub 网页端创建文件。这让 git bisect、git log -S 这类追溯手段基本失效 —— 本次 P0-1 的音乐回归，就是靠比对备份文件而不是提交历史才定位到的。

无障碍

Modal 无焦点陷阱

两页的弹窗（服务条款 / Intro）都做了 Esc 关闭和 body overflow:hidden，但打开后焦点没有移入弹窗，也没有 focus trap —— 键盘用户可以 Tab 到背后被遮挡的内容上。另外关闭后焦点不会回到触发按钮。补一个 10 行左右的焦点管理函数即可解决。

无障碍

下载卡片整块可点击，但键盘不可达

.dl-card 设了 cursor:pointer 并绑定 click，但它不是 <a> 也不是 <button>，没有 role、没有 tabindex、没有键盘事件。键盘和读屏用户完全无法触发这个快捷下载；而对触屏用户，它又增大了误触下载的概率。建议：给卡片加 role="button" tabindex="0" 并处理 Enter/Space，或者直接砍掉整卡点击、只保留按钮 —— 考虑到 VN 死链问题，后者更稳妥。

可用性

YouTube iframe 硬编码，无兜底

index.html 的社群区直接嵌入 youtube.com/embed/Mr6FaTdi9As。站点主体是中文用户，而这个资源在大陆网络环境下大概率加载失败，会留下一块空白的玻璃面板。建议改成点击后才加载的封面图（YouTube 缩略图 + 播放按钮），或换成 B 站源。

文案

两处文案硬伤

① 页脚「PaoMian Hax is a team that since 2099 brings quality services」—— 明显是占位文本忘了改，两个页面都有。
② 合规声明不一致：download.html 页脚写了 (Except China)，index.html 页脚漏了。配合 Hero 指向境内域名 mall.909net.cn 的「店鋪」按钮，这个声明本身的有效性也存疑 —— 建议统一口径后两页保持一致。

性能

静态资源无版本指纹

页面引用的 static/favicon.ico、static/music.mp3 都没有 hash 后缀，而 Cloudflare 给的缓存是 max-age=600。改了这些文件后，用户最长可能 10 分钟才看到更新。影响不大，但如果要做图片优化或换音乐，建议顺手加上 query 版本号。

仓库

.workbuddy/ 有 32 个文件被 git 跟踪

.gitignore 只忽略了 .workbuddy/backups/ 和 .workbuddy/memory/*.bak*，漏了 reports/ 与 tmp/。结果 10 张截图 PNG、6 个 tmp 中间文件、4 份分析报告、6 个 memory 日志全部进了仓库历史。建议补上：

信息架构

Hero 四个按钮语义重叠

Hero 区并排放了「店鋪」「下載 || Download」「Purchase」「>>_ Discord / 群 _<<」四个按钮，其中「店鋪」和「Purchase」指向的都是购买流程（且当前都不可用）。四个按钮在移动端会折成两行，视觉重心也散。建议收敛为两个主行动：下载 + 购买，社群入口降级为文字链。
