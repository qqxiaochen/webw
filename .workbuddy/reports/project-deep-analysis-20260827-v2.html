2. 部署架构真相（v2 新增）

⚠ 关键事实修正：工作记忆与 v1 报告均记录「GitHub Pages 托管，CNAME 绑定」。经实测与现状不符：线上站点托管在 Cloudflare，GitHub 仓库并非部署通道。
探测项实测结果结论
DNSwww.paomfz.com → 172.66.40.151（Cloudflare 边缘 IP）Cloudflare 代理
响应头Server: cloudflare，cf-cache-status: DYNAMIC，CF-RAY ...-BOMCloudflare 边缘

GitHub API /pagesHTTP 404 = 该仓库未启用 GitHub Pages与记录矛盾
线上 download.html 哈希a93c1dc… ≠ 本地 536f7d4b…，但链接已是最新版线上为另一份构建（疑混淆后发布）
线上 down/ph/9D759C3.zip206 可下载；本地该文件被 .gitignore 忽略、从未提交发布不走 git push

部署模型推断

P1 — 发布链路不清，存在「部署 = 手工上传 / Cloudflare Pages 直传」的痕迹。 git 仓库（origin/main）落后于线上：线上已引用 9D759C3.zip（本地未提交）、线上文件哈希与本地不同、线上 robots/404 均为 CF 默认。
含义：① git 只作源码留档，不是发布源；② 若服务器/账号丢失，无法从 git 完整重建线上；③「本地未提交 → 线上已在用」存在版本漂移风险。
P2 — 文档与实现不一致：记忆、README 类记录仍写 GitHub Pages，实际为 Cloudflare。建议在仓库 README 或部署说明中明确真实托管渠道，避免后续误操作。

11. 风险评估

P0 — 外挂分发法律/平台风险

公开提供游戏作弊工具下载，违反游戏 EULA，可能导致封号、法律纠纷、CDN/搜索引擎下架。属业务模式固有风险。

P0 — VN 死链仍在线

download.html 标记 VN「Updating」但链接 404，损害信任且浪费流量。

P0 — 发布链路与 git 脱节

线上=手工/Cloudflare 直传构建，git 落后（未提交 PH 链接、本地无 9D759C3、404/robots 线上未生效），存在「仓库≠线上」的不可重建风险。

P1 — 仓库 1.4GB 膨胀

历史二进制污染，克隆/CI 慢，接近平台限制红线。

P1 — 「HACK/CHEAT」关键词 + keywords 堆砌

可能被搜索引擎判垃圾信息。

P1 — 支付域名矛盾

Hero「店铺」链 mall.909net.cn（境内），Purchase 链 pay.paomfz.com——双支付入口且域名归属不统一。

P2 — 无隐私政策 / 无分析埋点

合规与转化数据均为空白。
